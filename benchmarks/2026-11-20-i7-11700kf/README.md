# KM Decimate 实际使用性能记录 · 2026-11-20

本次快照来自一台 Windows 工作站上的日常 ZBrush 减面任务，可用于选择回归测试规模、排查内存峰值和拆分等待时间。采集时使用 Intel Core i7-11700KF（8 核 16 线程）、约 32 GiB 内存、ZBrush 2026.2.1。安装面板标为 KM Decimate 0.3.1。采集时的核心程序 SHA-256 为 `09c61e8682ec2d5309053b15778dfa606a274e1d6d100ec3f84def2a2ce75b8e`。历史日志跨越多种字段格式，具体每次使用的构建版本未知。

| 文件 | 覆盖范围 |
|---|---|
| [worker.csv](worker.csv) | 173 次核心运行，含 168 次成功、2 次取消、3 次内存分配失败（`std::bad_alloc`）。成功输入覆盖 100 至 52,306,273 个三角形，100 次记录了峰值内存。 |
| [zbrush.csv](zbrush.csv) | 165 次 ZBrush 往返计时，含 164 条已追加日志和 1 条等待下次启动才会写入日志的最新计时。其中 137 条有推定的核心记录编号。 |

## 字段与单位

CSV 使用 UTF-8 和小数点，时间单位为秒。空单元格表示原日志缺少该字段，或无法推定对应记录。数值 0 保留其实际含义。

| 字段 | 含义 |
|---|---|
| `worker_seq`、`host_seq` | 本次快照内各自的记录序号，从 1 开始，按各自来源的写入顺序排列。 |
| `outcome` | 核心写出的结果，取值为 `success`、`cancelled`、`bad_alloc`。成功只表示核心完成写出。 |
| `keep_pct`、`target_triangles` | 请求的保留百分比；显式目标三角形数为 0 表示按百分比计算。 |
| `input_triangles`、`output_triangles` | 核心统计的三角形数，输入四边形会拆成三角形。 |
| `keep_group_borders`、`input_has_color`、`color_detail` | 是否保护组边界、输入是否带顶点色、颜色细节值。前两项为 0/1，颜色细节为 0 表示仅按形状减面。 |
| `threads`、`passes`、`target_chunk_triangles` | 核心线程数、处理遍数、分块的目标三角形数。 |
| `load_s`、`decimate_s`、`save_s` | 核心读取网格、计算减面和写出网格的耗时。 |
| `peak_commit_mib` | 核心进程的峰值提交内存，单位 MiB。ZBrush 进程和其他程序另占内存。 |
| `copied_subtool`、`reimported` | ZBrush 此次是否复制子工具、是否进行了第二次导入，均为 0/1。 |
| `export_s`、`worker_wait_s`、`import_s`、`total_s` | ZBrush 侧的导出准备与导出、等待核心、回导、全程耗时。等待包含核心读写和进程交接。回导包含导入后的整理，部分样本的全程另有收尾开销。 |
| `first_import_s`、`second_import_s` | 第一次与第二次实际导入的耗时。 |
| `job_text_write_result` | 兼容用任务文本的写入返回值，用于核对交接。此值可能重复。 |
| `source`、`inferred_worker_seq` | 往返计时来源（`timing_log` 或 `pending_timing`），以及可推定时对应的核心记录序号。 |

## 来源与配对方法

核心记录取自 `log.txt`。ZBrush 在一次操作结束时先写 `zb_last.zvr`，下次调用核心时，才把上一笔追加到 `zb_times.txt`。采集时一并读取了最后这条待写计时，核对了它与当前任务的编号、参数，并检查它此前未被追加。各行按原顺序保留。公开表仅选取性能数值、设置和结果类型。

两份日志没有共同的唯一运行编号，因此跨表联系属于推定。配对只考虑成功且回导耗时大于零的候选，要求保留百分比、颜色细节、任务文本写入返回值均有记录且相同。先在保持两边顺序的前提下求能配出的最多对数，再加上时间条件重算一次（核心读、算、写之和至多比 ZBrush 等待时间多 0.025 秒，以容许两侧计时精度差异）。只保留在**两套条件的所有最多配对方案中都出现**的同一对记录。其余 28 条往返计时保留空编号，仍可独立分析。
